# BUG-004: Last Name entered in the checkout form is not saved, which blocks checkout for `problem_user`

| Field | Details |
|---|---|
| **Severity** | High |
| **Priority** | P1 |
| **Status** | New |
| **Type** | Functional |
| **Component** | Checkout / Your Information form |
| **Reported by** | Herman Effendi |
| **Date reported** | 2026-10-28 |
| **Environment** | Brave Browser 156.1.98.60 , Ubuntu 24.04 , https://www.saucedemo.com |
| **Test account** | `problem_user` / `secret_sauce` |
| **Reproducibility** | [5] out of [5] attempts |

## Summary
In the checkout "Your Information" form, text typed into the **Last Name** field is not kept in that field (the value ends up in another field or the field stays empty). The form then rejects the submission, so the customer cannot complete checkout.

## Preconditions
- The user is logged in as `problem_user`.
- At least one product is in the cart. Use a product that can be added successfully (see BUG-001).

## Steps to Reproduce
1. Open https://www.saucedemo.com and log in as `problem_user` / `secret_sauce`.
2. Add a product to the cart and click the cart icon.
3. Click **Checkout**.
4. Enter First Name `Budi`.
5. Enter Last Name `Santoso`.
6. Enter Postal Code `12345`.
7. Observe the contents of all three fields before submitting.
8. Click **Continue**.

## Expected Result
- Each field keeps the value that was typed into it (`Budi`, `Santoso`, `12345`).
- Clicking **Continue** opens the overview page (`/checkout-step-two.html`).

## Actual Result
- The value typed into Last Name is not retained in that field.
- Clicking **Continue** shows an error and stays on `/checkout-step-one.html`.

## Evidence
- Screenshot of the form before clicking Continue: `evidence/bug-004-form.png`
- Screenshot of the error after clicking Continue: `evidence/bug-004-error.png`
- Control: as `standard_user`, the same data completes checkout and reaches the order overview.
- Automated test: `tests/known-bugs.spec.ts`, "BUG-004: Last Name is not saved in the checkout form" (marked with `test.fail()` while the bug exists).

## Impact
- **User:** the customer cannot place an order and has no way to fix the form because the correct input is rejected.
- **Business:** blocks the final step of the purchase flow and causes direct revenue loss.
- **Severity rationale:** High. A critical flow is blocked, and no workaround was found.
- **Priority rationale:** P1. It should be fixed together with BUG-001, since both block purchasing.

## Possible Cause (hypothesis, not confirmed)
The input handler for the Last Name field may be bound to the wrong form field. Black-box observation only.

## Suggested Fix
Bind each form field to its own state and add form tests that check the value of every field after typing.

## Workaround
None found.

## Retest Criteria
- All three fields keep their typed values.
- Checkout completes and the confirmation message "Thank you for your order!" appears.
- The automated test for BUG-004 fails after the fix, which signals that `test.fail()` should be removed.
