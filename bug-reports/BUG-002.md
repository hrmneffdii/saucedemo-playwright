# BUG-002: Product sorting does not change the product order for `problem_user`

| Field | Details |
|---|---|
| **Severity** | Medium |
| **Priority** | P2 |
| **Status** | New |
| **Type** | Functional |
| **Component** | Inventory page / Sort dropdown |
| **Reported by** | Herman Effendi |
| **Date reported** | 2026-10-28 |
| **Environment** | Brave Browser 156.1.98.60 , Ubuntu 24.04 , https://www.saucedemo.com |
| **Test account** | `problem_user` / `secret_sauce` |
| **Reproducibility** | [5] out of [5] attempts |

## Summary
On the inventory page, selecting any option in the sort dropdown (name or price) does not reorder the products when logged in as `problem_user`.

## Preconditions
- The user is logged in as `problem_user` and is on the inventory page.
- The sort dropdown is on its default option (Name A to Z).

## Steps to Reproduce
1. Open https://www.saucedemo.com and log in as `problem_user` / `secret_sauce`.
2. Note the order of the 6 products and their prices.
3. Open the sort dropdown (top-right of the product list) and select **Price (low to high)**.
4. Compare the product order and prices with the order noted in step 2.
5. Repeat with **Price (high to low)** and **Name (Z to A)**.

## Expected Result
| Option | Expected order |
|---|---|
| Price (low to high) | 7.99, 9.99, 15.99, 15.99, 29.99, 49.99 |
| Price (high to low) | 49.99, 29.99, 15.99, 15.99, 9.99, 7.99 |
| Name (Z to A) | Test.allTheThings() T-Shirt (Red), Sauce Labs Onesie, Fleece Jacket, Bolt T-Shirt, Bike Light, Backpack |

## Actual Result
The product order stays the same as in the default view after each selection. 

## Evidence
- Screenshots before and after selecting Price (low to high): `evidence/bug-002-before.png`, `evidence/bug-002-after.png`
- Control: as `standard_user`, the same selection reorders the products correctly.
- Automated test: `tests/known-bugs.spec.ts`, "BUG-002: sorting does not change the order" (marked with `test.fail()` while the bug exists).

## Impact
- **User:** customers cannot quickly find the cheapest or most expensive product and must scan manually.
- **Business:** lowers usability and may reduce conversion, but does not block purchasing.
- **Severity rationale:** Medium, because a workaround exists (manually scanning the 6 products). On a catalog with many products the impact would be higher.

## Possible Cause (hypothesis, not confirmed)
The sort selection may not trigger the re-render of the product list. Black-box observation only.

## Suggested Fix
Ensure the selected sort option updates the displayed list, and add a regression test per sort option (4 options).

## Workaround
Scan the list manually.

## Retest Criteria
All 4 sort options produce the expected order from the table above.
